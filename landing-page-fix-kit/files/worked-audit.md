## F1: lower contents list changes the offer promise
- **Criterion/status:** M2/O3, **Needs work**.
- **Provenance:** **observed** R1 copy. Recommendation below is **proposed**.
- **Finding type:** **observed defect** — internal copy/offer contract inconsistency.
- **Evidence:** R1 header “FREE 23-PAGE GUIDE + DEMO KIT”; intro “Connect tools with MCP, retrieve an approved brief, and turn it into a useful marketing draft. Start with a read-only demo, then learn how to connect a real service safely.”[1]
- **Conflicting section:** R1 WHAT YOU GET contains “A practical operating guide, not another model leaderboard.” followed by “One-page Claude model decision tree”, “Four-part task complexity test”, “Tool-use guide for Claude.ai, Claude Code, Cowork, and Fable”, “Fourteen copy-ready prompts across all three paths”, and “Seven-day implementation plan”.[1]
- **Interpretation:** the lower list switches from an MCP connection/brief-to-marketing workflow to model selection, task complexity and multi-tool path planning. These are materially different stated contents. The mismatch is visible in the copy; its origin is unknown.
- **Not established:** what the PDF truly contains, whether any visitor is confused, impact on conversion, traffic expectations or delivery success. No claim about visuals.
- **Priority:** correct the evidenced product-identity contradiction before optimization experiments; no revenue estimate.
- **Smallest correction, proposed and owner-gated:** inspect the actual guide/demo kit, then align the lower list to the authoritative resource. If the resource confirms the intro, candidate replacements are: “MCP client, server and service roles”; “Read-only fictional-brief demo”; “Source-fact retrieval before drafting”; “Permission and output verification checkpoints”. These are candidate summaries of existing page promises, not verified PDF contents. Remove/replace incompatible bullets only after owner confirmation; do not add invented quantities, deliverables or a new offer.
- **Alternative if resource differs:** if the PDF supports the lower list instead, the owner must decide which product belongs on this route before any rewrite. Do not silently assume the hero is authoritative.
- **Acceptance:** owner supplies exact PDF/demo kit/version; inspect contents and page count; compare final hero, intro, WHAT YOU GET, CTA and delivery-resource identity. Request refreshed copy and desktop/mobile captures; this audit does not implement changes.
- **Optional test hypothesis:** aligning verified contents may reduce offer-comprehension errors. Measure a defined comprehension task or owner-approved request/access metric only after baseline and evaluation rule are supplied. No lift forecast or causal conclusion.
